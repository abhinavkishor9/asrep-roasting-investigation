# Lab 81 — Investigation Notes

## 1. Host Environment Validation

The first step was to determine whether the workstation was part of an Active Directory environment.

The following command was used:

```powershell
Get-CimInstance Win32_ComputerSystem |
Select-Object Name, Domain, PartOfDomain, DomainRole
```

Observed result:

```text
Name         : DESKTOP-9MMM37V
Domain       : WORKGROUP
PartOfDomain : False
DomainRole   : 0
```

The endpoint is therefore a standalone WORKGROUP workstation.

This is significant because the core Kerberos events required for this investigation are generated by the Domain Controller/KDC rather than by a normal standalone workstation.

## 3. Kerberos Client Validation

The native Windows Kerberos utility was explicitly executed using:

```powershell
& "$env:SystemRoot\System32\klist.exe"
```

The ticket cache was then checked with:

```powershell
& "$env:SystemRoot\System32\klist.exe" tickets
```

Observed result:

```text
Current LogonId is 0:0x47dc3

Cached Tickets: (0)
```

This establishes that no cached Kerberos tickets were present in the inspected logon session at the time of collection.

The result does not establish whether Kerberos activity occurred elsewhere.

An empty ticket cache is therefore not treated as evidence that AS-REP Roasting did not occur.

## 4. Event ID 4768 Investigation

Event ID 4768 was searched in the local Security log.

The initial query returned:

```text
No local Security Event ID 4768 events found.
```

A second query attempted to parse available 4768 events and extract:

- `TargetUserName`
- `ClientAddress`
- `PreAuthType`
- `TicketEncryptionType`

The query returned:

```text
Get-WinEvent: No events were found that match the specified selection criteria.
```

No local 4768 event was therefore available for analysis.

This means the investigation could not validate the critical condition:

```text
PreAuthType = 0
```

The absence of local 4768 telemetry is consistent with the endpoint being a standalone WORKGROUP workstation rather than a Domain Controller.

---

## 5. Event ID 4771 Investigation

The local Security log was also checked for Event ID 4771.

No events were returned.

Event ID 4771 is associated with Kerberos preauthentication failures on Domain Controllers.

Its absence from this workstation therefore does not provide meaningful evidence against AS-REP Roasting.

There is also an important detection limitation:

```text
No 4771
    ≠
No AS-REP Roasting
```

Accounts configured not to require Kerberos preauthentication do not generate the normal preauthentication-failure event.

## 6. Active Directory Account Validation

The investigation attempted to identify accounts configured with `DONT_REQ_PREAUTH`.

The command used was:

```powershell
Get-ADUser -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=4194304)" `
-Properties UserAccountControl |
Select-Object SamAccountName, UserPrincipalName, UserAccountControl
```

PowerShell returned:

```text
Get-ADUser: The term 'Get-ADUser' is not recognized as a name of a cmdlet, function, script file, or executable program.
```

This indicates that the ActiveDirectory PowerShell module is unavailable.

The account flag being investigated is:

```text
DONT_REQ_PREAUTH
```

which corresponds to:

```text
0x400000
```

The check could not be performed on this endpoint.

This was not treated as a failed attack investigation step. It was documented as an environmental limitation.

The endpoint is not domain joined and therefore does not provide a local Active Directory environment for `Get-ADUser` to enumerate.

## 7. Sysmon Process Investigation

Sysmon Event ID 1 was queried using:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "Microsoft-Windows-Sysmon/Operational"
    Id = 1
} -MaxEvents 200 |
Select-Object TimeCreated, Message
```

Multiple process creation events were returned.

The visible output contained entries such as:

```text
Process Create:...
```

The results confirm that process creation telemetry is functioning.

However, the displayed event information was abbreviated.

There was therefore insufficient evidence to associate a specific process with AS-REP Roasting.

The process telemetry was retained as supporting evidence rather than being treated as proof of malicious activity.

## 11. Investigation Reasoning

The key finding is not simply that no suspicious Kerberos event was observed.

The more accurate finding is that the endpoint does not provide the telemetry source required to establish the relevant Kerberos activity.

The distinction is:

```text
No local 4768
```

versus:

```text
No AS-REP Roasting occurred
```

The investigation supports only the first statement.

The workstation is not a Domain Controller and is not joined to an Active Directory domain.

Therefore, the absence of local 4768 and 4771 events is primarily a telemetry and environment limitation.

---

## 12. Classification

### Inconclusive

The investigation is classified as **Inconclusive** because:

- the endpoint is not domain joined
- the endpoint is not a Domain Controller
- no local 4768 events were available
- no local 4771 events were available
- the ActiveDirectory PowerShell module was unavailable
- `DONT_REQ_PREAUTH` account configuration could not be validated
- Sysmon did not provide sufficient evidence to associate a process with AS-REP Roasting
- Wazuh provided contextual activity but not the required Kerberos evidence
