# Troubleshooting Notes

## 1. Active Directory PowerShell Module Was Unavailable

### Command

```powershell
Get-ADUser -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=4194304)" `
-Properties UserAccountControl |
Select-Object SamAccountName, UserPrincipalName, UserAccountControl
```

### Result

```text
Get-ADUser: The term 'Get-ADUser' is not recognized as a name of a cmdlet, function, script file, or executable program.
```

### Cause

The ActiveDirectory PowerShell module is not installed or available on the investigated endpoint.

The endpoint also reports:

```text
Domain       : WORKGROUP
PartOfDomain : False
DomainRole   : 0
```

Therefore, the workstation is not part of an Active Directory domain and does not provide a local AD environment for `Get-ADUser` to query.

### Resolution

The module was not installed merely to manufacture an Active Directory result.

The limitation was documented instead.

A genuine `Get-ADUser` investigation requires access to an Active Directory environment, normally from a domain-connected administrative or security workstation.

## 2. Event ID 4768 Was Not Found

### Command

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "Security"
    Id = 4768
} -MaxEvents 20 -ErrorAction SilentlyContinue
```

### Result

```text
No local Security Event ID 4768 events found.
```

A second query attempting to parse Event ID 4768 returned:

```text
Get-WinEvent: No events were found that match the specified selection criteria.
```

### Cause

Event ID 4768 is generated by the Kerberos Authentication Service on a Domain Controller.

The investigated system is:

```text
WORKGROUP
DomainRole 0
```

It is therefore not the expected source for Domain Controller-side 4768 telemetry.

### Resolution

Treat the result as an environment and telemetry limitation.

Do not interpret it as proof that AS-REP Roasting did not occur.

## 3. Event ID 4771 Was Not Found

### Command

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "Security"
    Id = 4771
} -MaxEvents 100 -ErrorAction SilentlyContinue |
Select-Object TimeCreated, Id, Message
```

### Result

No events were returned.

### Interpretation

Event ID 4771 is associated with Kerberos preauthentication failures on Domain Controllers.

The investigated workstation is not a Domain Controller, so the absence of local 4771 telemetry is expected to be treated as a telemetry limitation.

There is also an important AS-REP Roasting limitation:

```text
No 4771
    ≠
No AS-REP Roasting
```

Accounts configured not to require Kerberos preauthentication do not generate the normal preauthentication-failure event.

### Resolution

Document the absence of 4771 without using it to exclude AS-REP Roasting.

## 4. Kerberos Ticket Cache Was Empty

### Commands

```powershell
& "$env:SystemRoot\System32\klist.exe"
```

and:

```powershell
& "$env:SystemRoot\System32\klist.exe" tickets
```

### Result

```text
Current LogonId is 0:0x47dc3

Cached Tickets: (0)
```

### Interpretation

The inspected logon session contained no cached Kerberos tickets at the time of collection.

### Important Limitation

An empty ticket cache does not establish:

```text
No Kerberos activity occurred.
```

It establishes:

```text
No cached Kerberos tickets were present in the inspected session.
```

The full Windows path was used to ensure that the Windows `klist.exe` executable was executed rather than another executable with the same command name.

## 5. Sysmon Event ID 1 Was Available

### Command

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "Microsoft-Windows-Sysmon/Operational"
    Id = 1
} -MaxEvents 200 |
Select-Object TimeCreated, Message
```

### Result

Multiple process creation events were returned.

The visible output included:

```text
Process Create:...
```

### Interpretation

Sysmon process creation telemetry is functioning.

However, the displayed event information was abbreviated.

The available evidence therefore does not establish that a specific process performed AS-REP Roasting.

### Resolution

For future process-level correlation, retrieve the complete event details or XML.

Do not classify an executable as malicious solely because it appears around the investigation timeframe.

## 7. Wazuh Account Discovery Alerts Were Present

Wazuh displayed detections including:

```text
A net.exe account discovery command was initiated
```

### Interpretation

This is relevant endpoint reconnaissance activity.

It does not establish AS-REP Roasting.

The required Kerberos chain remains:

```text
4768
+
PreAuthType = 0
+
Target account
+
DONT_REQ_PREAUTH
```

None of these core Domain Controller-side indicators were available from the current endpoint.

### Resolution

Keep the Wazuh activity as contextual evidence.

Do not label the activity as AS-REP Roasting without corroborating Kerberos telemetry.

## 8. Wazuh Alerts vs Wazuh Archives

A proper investigation should distinguish between telemetry collection and detection.

If a 4768 event exists in Wazuh archives but no corresponding alert exists:

```text
Underlying telemetry exists
        ↓
Detection rule may be missing
```

This represents a detection-rule or alerting gap.

If the 4768 event does not exist in Wazuh archives:

```text
Underlying telemetry unavailable
        ↓
Collection or forwarding problem
```

This represents a telemetry collection or forwarding issue.

These are different SOC problems and should not be combined.

## 9. Do Not Manufacture Kerberos Events

No artificial Event ID 4768 or 4771 events were generated during this investigation.

This was intentional.

Creating artificial events could demonstrate that a command can produce a log entry, but it would not represent a realistic Active Directory investigation.

The lab instead documents:

- what telemetry was available
- what telemetry was missing
- why the missing telemetry matters
- how the investigation should be classified
